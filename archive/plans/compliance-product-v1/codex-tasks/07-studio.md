# Build the review and authoring studio

## Instruction

Build a thin React interface for source inspection, passage anchoring, claim/action review, duplicate resolution, methodology editing, diagnostics, scenario tests, evaluation proof trees, benchmark discrepancies, and release comparison.

Acceptance: a reviewer can trace any score to source passages in three interactions or fewer; unresolved and contested evidence are visually distinct; no UI action bypasses API authorization or semantic validation; keyboard and screen-reader paths work.

## Non-goals

Do not redesign settled ADRs without opening a replacement ADR. Do not add broad infrastructure that is not required by the acceptance criteria. Do not hide incomplete behavior behind mocks in production paths.
