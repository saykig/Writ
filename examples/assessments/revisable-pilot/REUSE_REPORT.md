# Executed Writ–Vela reuse probe

## Result and boundary

The real Vela 0.977.6 CLI retained exact Writ artifacts as authenticated pending
Submissions. A separate temporary checkout passed Vela replay and then Writ's
existing recipient CLI freshly checked the preserved alpha/beta candidates. A
second Submission carries the native two-revision archive and an explicit mapping
back to the first Claim/Submission. Native replay reconstructs both revision impacts.
A scoped Vela Verification Record was recorded after the actual Writ receiving run.
All Claims remain pending: **zero accepted Claims and zero accepted-state changes**.

The CLI rejected `--corrects` for the first pending Claim because its correction
contract requires an accepted target. The supported fallback is a separate pending
Submission with exact Writ revision/mapping artifacts. Writ, not a fabricated Vela
accepted-state edge, remains responsible for that correction's meaning. Vela also
has no current CLI for authoring general dependency edges. This is an executed
bounded interoperability result, not adoption of a shared ontology or a complete
semantic transport of Writ applicability into Vela Standing.

## Failed exploratory attempts

Before retaining this probe, Bun was absent from PATH and root examples could not
resolve package aliases; the existing Bun binary and relative public entrypoints
resolved those invocation issues. The first native script passed a loaded workspace
where recipient replay requires exported bytes; that API error was corrected and
a fresh output directory received the successful run. A temporary ssh-agent expired
between commands; the Verification attempt failed before record creation. The retry
owned its disposable agent for the full invocation and succeeded. None of these
attempts is counted as an AI recipient run or a successful compatibility check.

Next implementation work is a small replay/adapter command with decisive mutation
controls and cleanup of the synthetic trust fixture, followed by the prospectively
frozen continuation pilot and local interface. No fork or Vela core change is needed
for the supported artifact route; general dependency-edge authoring would require a
separate upstream contract change and is not attempted here.
