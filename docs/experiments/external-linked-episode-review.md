## Review and decisive controls

The external receiver checks the complete pinned source/model/input scope before numerical use;
changing recorded package code or adapter identity fails even with a refreshed envelope hash.
A replacement output fails its retained pin; refreshing hashes still cannot make a false trace pass
the independent recurrence. Structured empirical, causal, Bellman-certificate and unsupported-unit
promotions reject. Local execution is recorded, not cryptographically authenticated at receiving.

The link checks both independently supplied episode pins, named parent observation/reconsideration,
actual old/new service times, complete external input diff and supplied event order. Wrong event,
stale episode pin, replaced observation/output and unsupported effect/supersession claims reject.
One stronger control changes an arrival while maintaining a numerically valid revised trace and
refreshing all run/input/episode/link hashes: the link rejects the undeclared extra input change.
Internal consistency is therefore not confused with the narrower declared revision warrant.

Actual relocated receiving runs with native `solve` disabled and the external producer disabled.
It reopens both embedded episodes through their public receivers, checks four native execution
instances and both transport warrants, and separately checks both external traces. The retained
receiving checkpoint never substitutes for a future fresh check. No new exact native certificate,
causal result, empirical observation, source validation or actor authentication is earned.

## Maintenance and proposed disposition

Recommend keeping the two bounded additions for review. They make external model results inspectable
without laundering them into exact-native status, and let a later author resolve why an explicit
reconsideration led to a changed model run. The benefit is scoped interoperability and revision
accountability, not stronger mathematics, speed, file counts or an empirical benchmark.

Added surface: two closed schemas with TypeScript mirrors, one external receiving operation,
three pair operations (create/open/replay), two small CLIs, six diagnostics, and one explicitly
invoked Python model adapter/producer. SimPy is not a default Writ dependency. Native exact JSON,
byte hashing, schema validation, episode and mathematical receivers are reused. Source pin updates
and schema/type mirrors are real maintenance costs; broader SimPy features are unsupported.
Standalone episode APIs and the existing native schemas are unchanged.

The pair intentionally embeds both native episodes, and standalone fixture copies are also retained.
This increases artifact size (the example link is about 576 KiB) but makes receiving independent of a
path resolver or storage registry. A future scale requirement could justify deduplication; none is
claimed here. The link supports one service-duration revision with the native history unchanged,
not arbitrary graphs, multiple model families or automatic native reassessment. Do not generalize
those interfaces absent another concrete operation.

Vela-inspired overlap is useful context, not a removal criterion. Vela's pending/accepted Claim and
Verification semantics do not replace Writ's supplied operational choices. Bellman and Decision Lab
were inspected at current main; existing contracts suffice for native checking. No mathematical or
tooling gap justified a new cross-repository build. A later decision-theoretic use of simulated
outputs must first justify units, likelihoods/losses and empirical applicability explicitly.
