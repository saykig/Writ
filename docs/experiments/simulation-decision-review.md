# Simulation-to-decision build and review — PR #53

**Status:** bounded authorized addition under Proposed ADR 0029. This report does not accept the ADR,
merge the PR, validate a real queue or authorize an action.

## Earned operation

The build connects the already received external FIFO model to one explicit decision subject. Three
options change the exact service input through declared offsets from one supplied base-service
assumption. Every option is run through the actual pinned SimPy 4.1.1 producer and independently
received through Writ's integer FIFO recurrence before numerical use.

The comparison binds a complete declared menu, option/action identities, raw run/input/output/model
bytes, model/runtime/source pins, minutes, fixed costs, a positive integer wait weight, stipulated
loss-point units, the exact objective formula, preference statement, no rounding and zero tolerance.
The receiver recomputes every loss and the complete minimizing option set with BigInt arithmetic.
Real-world option completeness and empirical applicability remain `not_established`.

Under the supplied synthetic preferences:

| Base service | Intensive | Retain | Streamline | Conditional minimum |
| ---: | ---: | ---: | ---: | --- |
| 5 minutes | 7 | 2 | 4 | retain |
| 9 minutes | 9 | 10 | 10 | intensive |

Losses are stipulated loss points. The rank change follows exactly from the supplied queue model and
objective; neither the base times, option deltas nor burdens are empirically identified.

One immutable revision changes only base service from 5 to 9 minutes. It enumerates all three derived
service/input/run changes and preserves both comparison records. Both decision episodes retain the
same unrelated native A/B checked history. The parent synthetic decision selects `retain`, while the
successor selects `seek_empirical_service_evidence` outside the represented menu despite the new
conditional preference. The derived disposition relation is exact, but the human acts remain
supplied and authority is never inferred.

## Why a Writ contract rather than only a script

A competent direct script can receive the five runs, compute the same exact waiting totals and add
the same fixed costs. It remains the simpler route for a one-off answer. The Writ contract earns only
portable safeguards useful for later inspection:

- the reviewed whole-comparison identity is required independently of received bytes;
- model output, normative mapping, conditional preference, applicability and authority are typed
  separately;
- the complete declared menu and full minimizing set are retained, including exact ties;
- the successor records every model input/run change and rejects an undeclared semantic change;
- both old and new comparisons remain reconstructable rather than replacing history; and
- a relocated producer-disabled recipient rechecks both comparisons and both native episode
  histories, then reports the human dispositions separately.

Those are provenance and correction benefits, not stronger mathematics or evidence.

## Decisive controls

Focused comparison/revision tests cover valid unique minima, an exact-tie control, wrong units,
wrong loss mapping, nonzero tolerance, stale outputs, substituted option input, substituted model,
false preferred option, stale whole-artifact identity, incomplete option-change declaration,
misstated assumption value, undeclared option-semantics change, false human-disposition relation,
substituted episode pin and changed native history.

The relocated integration runs with `WRIT_DISABLE_EXTERNAL_PRODUCER=1` and a Python wrapper that
refuses Decision Lab `solve`. It freshly checks both external comparison subjects, both original and
successor native execution sets and both certificate-transport warrants. Stored check labels and
prior receipts are not receiving authority.

## Maintenance and limits

Added maintained surface: two closed JSON Schemas, two TypeScript receiver modules, one CLI, one
generator, three new external input/run pairs, two unit suites and one real integration. SimPy
remains an optional explicitly invoked producer, not a Writ dependency. Broader queue behavior,
another objective mapping or another revision field is unsupported and requires another bounded
contract or version.

The revision artifact embeds both comparisons and both episodes, so it is about 620 KiB. This keeps
the handoff independent of a resolver/registry at the cost of duplication. No demonstrated scale
need justifies deduplication infrastructure.
