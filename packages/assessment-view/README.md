# Local revisable assessment notebook

Experimental file-based view for the bounded OPERA pilot. It reads the frozen source
packets, shows three historical stages, preserves the synthetic analyst disagreement,
and exports an authored A1 continuation request. It is not a native scientific record,
political record, inference engine, accepted assessment, or new Bellman operation.

The separate native panel uses `openSharedAnalysis` and `inspectSharedAnalyses` from
`@writ/shared-analysis` to inspect the exact archive exercised through Vela. Its replay
is explicitly retained evidence. The export preserves native archive bytes so the
existing Writ recipient can freshly check them. No OPERA claim inherits that check.

From repository root, with Bun on PATH and the native archive generated by the
[reuse exercise](../../examples/assessments/revisable-pilot/REUSE_REPORT.md):

```sh
bun packages/assessment-view/src/cli.ts init /tmp/assessment-history.json
bun packages/assessment-view/src/cli.ts view /tmp/assessment-history.json \
  /path/to/stage-2.archive.json /tmp/assessment.html
```

Open the HTML locally. Inspect the dated stages and sources. Choose a current use of
A1, write a rationale, and generate the request. Inspect the visible JSON, then save
`continuation-request.json` or select and copy its text into a plain-text file. A save
request is not confirmation that the browser saved a file. That request is a
proposal; it has no acceptance or authority effect. The form binds it to the entire
loaded history, regardless of which earlier stage is selected for inspection.

```sh
bun packages/assessment-view/src/cli.ts apply /tmp/assessment-history.json \
  /path/to/continuation-request.json /tmp/revised-history.json
WRIT_DISABLE_ASSESSMENT_PRODUCER=1 bun packages/assessment-view/src/cli.ts receive \
  /tmp/assessment-history.json /path/to/continuation-request.json /tmp/revised-history.json
bun packages/assessment-view/src/cli.ts view /tmp/revised-history.json \
  /path/to/stage-2.archive.json /tmp/revised-assessment.html
```

Outputs use exclusive creation. Existing records are never overwritten. The receiver
checks source excerpt identities, declared references, exact base identity, the
permitted request fields and exact append-only history. Structural equality preserves authored Unicode code points
even when Writ Canonical JSON would normalize two spellings to the same identity. It does not call the append
producer. Both share validation and Writ Canonical JSON v1 hashing, so this is operation
reconstruction, not an independent implementation of the provenance library. Parent
page hashes/spans are supplied provenance; excerpt-length/hash checks do not retrieve
or authenticate the full publisher page. No live network enters deterministic checks.

The profile accepts only one supplied assessment and a bounded authored A1 position.
It deliberately does not evaluate prose, propagate physical truth, reinterpret native
mathematical revisions, or promote a proposal to a human disposition. Static stage
summaries are authored display copy; appended positions appear separately below the
form. No persistent service, server, database, deployment or framework is introduced.
